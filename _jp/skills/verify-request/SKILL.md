argument-hint: <title>（例: アイコンの非同期化）[--run <id>] [--workflow <name>]

---

次のコマンドを実行する:

```bash
bash "${CLAUDE_SKILL_DIR}/verify-request.sh" $ARGUMENTS
```

その後、生成されたファイルを開いて埋める。**成果物の表は編集しない** — 成果物から
測ったものである。**報告の書式も編集しない** — その「未了・判定できなかった項目」の
見出しを、次回の実行が読んで項目を持ち越す。それ以外の節はすべて自分で書く。

完了を報告する前に、次の 4 つをすべて確かめる:

1. **測ったこと / 推測していること** が埋まっている。どちらか示していない主張は許されない。
2. すべての項目に **対照** がある。無い場合は「無し（確認のみ）」と書かれ、
   対照が無い項目 の節にその理由と、それでも何が言えるかが説明されている。
3. `0` を期待するすべての項目が **`0` を期待値に置いた項目** の表にあり、
   `1` になる場面か、数えている文字列が配布バイナリに存在する証拠が添えられている。
4. 事実は以前の文書から写したのではなく、**いま取り直した**ものである — パスとレジストリ
   キーは製品から、数字は成果物から読んだ。

生成されたファイルのパスと、スクリプトが測れなかったものを報告する。
