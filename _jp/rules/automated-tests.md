# 自動テスト

プロジェクトを始めるとき、および何を自動テストにするか決めるときに読む。

**境界は初日に引く。** 実装を始める前に、対象の OS やハードウェアが無くてもテストできる
コードを決め、そのテストを最初のコミットから CI に入れる。

- 「全部 UI / プラットフォームのコードだから」を理由に判断を先送りしない。純粋なロジック
  （整形、引数の解析、シリアライズの往復、パスの判定、比較関数、ツリーの形）は
  たいてい数千行あり、まさに気づかれない破損が潜む場所である
- テストのステップは publish/package のステップの**前**に置き、失敗したら成果物が作られないようにする
- 境界は `docs/testing.md` に記録する：何がカバーされているか、何が対象環境を必要とし、
  そのため手動の確認ループに残るか、そしてその理由
